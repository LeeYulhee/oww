# 오운완 프로젝트 테스트 코드 가이드

## 📋 테스트 구조 개요

### 1. 테스트 분류
- **단위 테스트 (Unit Tests)**: 개별 메서드나 클래스 테스트
- **통합 테스트 (Integration Tests)**: 여러 컴포넌트 간의 상호작용 테스트  
- **슬라이스 테스트 (Slice Tests)**: 특정 레이어만 테스트

### 2. 테스트 패키지 구조
```
src/test/java/
├── flobitt/oww/
│   ├── IntegrationTestBase.java          # 통합 테스트 기본 클래스
│   ├── TestFixtures.java                 # 테스트 데이터 생성 유틸
│   ├── TestDataCleanup.java             # 테스트 데이터 정리
│   ├── CustomAssertions.java            # 커스텀 Assertion
│   ├── api/                             # 컨트롤러 테스트
│   ├── domain/user/service/             # 서비스 레이어 테스트
│   ├── domain/user/repository/          # Repository 테스트
│   ├── domain/user/entity/              # Entity 테스트
│   ├── global/scheduler/                # 스케줄러 테스트
│   ├── integration/                     # 통합 테스트
│   ├── slice/                          # 슬라이스 테스트 기본 클래스
│   └── config/                         # 테스트 설정
```

## 📝 테스트 코드 작성 패턴

### 1. Given-When-Then 패턴
```java
@Test
@DisplayName("회원가입 성공 시 사용자가 저장된다")
void signUp_Success() {
    // given (테스트 데이터 준비)
    CreateUserReq request = CreateUserReq.builder()
            .userLoginId("testuser")
            .email("test@example.com")
            .password("Test123!@#")
            .build();

    // when (테스트 실행)
    authFacade.signUp(request);

    // then (결과 검증)
    Optional<User> savedUser = userRepository.findByEmailAndIsDeletedFalse("test@example.com");
    assertThat(savedUser).isPresent();
    assertThat(savedUser.get().getUserLoginId()).isEqualTo("testuser");
}
```

### 2. 테스트 헬퍼 메서드 활용
```java
// TestFixtures.java를 활용한 테스트 데이터 생성
User user = TestFixtures.createUser("test@example.com", "testuser");
EmailVerification verification = TestFixtures.createEmailVerification(user, "token");

// CustomAssertions를 활용한 유창한 검증
assertThat(user).hasEmail("test@example.com").isNotVerified();
assertThat(verification).hasToken("token").isNotExpired();
```


### 2. 테스트 데이터 관리
```java
// TestFixtures 사용 권장
User user = TestFixtures.createUser("test@example.com", "testuser");

// 직접 생성보다는 팩토리 메서드 활용
User verifiedUser = TestFixtures.createVerifiedUser("verified@example.com", "verifieduser");
```

### 3. Assertion 활용
```java
// 기본 AssertJ
assertThat(user.getEmail()).isEqualTo("test@example.com");

// 커스텀 Assertion 활용 (더 읽기 쉬움)
assertThat(user).hasEmail("test@example.com").isNotVerified();
```

### 4. 예외 테스트
```java
@Test
@DisplayName("존재하지 않는 이메일로 조회 시 예외 발생")
void findByEmail_UserNotFound_ThrowsException() {
    assertThatThrownBy(() -> userService.findByEmailAndIsDeletedFalse("nonexistent@example.com"))
            .isInstanceOf(IllegalArgumentException.class)
            .hasMessageContaining("유효한 회원 정보가 없습니다");
}
```

## 🎓 테스트 학습 포인트

### 1. 테스트 더블(Test Double) 이해
- **Stub**: 미리 정의된 답변을 반환
- **Mock**: 호출 여부와 방법을 검증
- **Spy**: 실제 객체를 부분적으로 모킹

### 2. 테스트 격리(Test Isolation)
- 각 테스트는 독립적으로 실행되어야 함
- `@Transactional` 또는 데이터 정리 로직 사용

### 3. 테스트 피라미드
- **단위 테스트**: 빠르고 많이
- **통합 테스트**: 적당히
- **E2E 테스트**: 적게, 중요한 플로우만

### 4. 테스트 컨테이너 활용
- 실제 데이터베이스 환경에서 테스트
- 개발 환경과 동일한 조건에서 검증
